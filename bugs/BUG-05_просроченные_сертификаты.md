# BUG-05. В `TrustedPublisher` ставится просроченный сертификат (+ сертификат сторонней организации)

* **Важность:** средняя (ИБ/жизненный цикл; скрытая деградация доверия к подписи драйвера)
* **Компонент:** установщик, секция 0, шаги 752–787
* **Инструкции (установщик):** 752, 755, 760, 763, 768, 771, 776, 779, 784, 787

## Суть

Установщик кладёт 5 сертификатов (`certutil -addstore`), в том числе два
сертификата издателя в хранилище «Доверенные издатели»:

```
776  Push "$\"$Var51\SYSTEM32\certutil.exe$\" -addstore $\"TrustedPublisher$\" $Var52\AMICLIENT\AmiCert_o1.cer"
784  Push "…-addstore $\"TrustedPublisher$\" $Var52\AMICLIENT\AmiCert_o2.cer"
```

Сроки действия получены разбором DER-структуры самих файлов
(`../extracted/payload/AmiCert_*.cer`):

| Файл | Субъект | Издатель | Действует | Хранилище |
|---|---|---|---|---|
| `AmiCert_r1.cer` | CN=AAA Certificate Services (Comodo) | самоподписанный | 2004-01-01 … 2028-12-31 | `Root` |
| `AmiCert_r2.cer` | CN=Sectigo Public Code Signing Root R46 | AAA Certificate Services | 2021-05-25 … 2028-12-31 | `CA` |
| `AmiCert_r3.cer` | CN=Sectigo Public Code Signing CA EV R36 | Sectigo Public Code Signing Root R46 | 2021-03-22 … 2036-03-21 | `CA` |
| `AmiCert_o1.cer` | CN=AMIKON, OOO, O=AMIKON, OOO, ST=Moskva, C=RU (ИНН 1027739070589) | Sectigo … EV R36 | **2021-11-01 … 2024-10-31 (истёк)** | `TrustedPublisher` |
| `AmiCert_o2.cer` | CN=STR ARM LLC, O=STR ARM LLC, ST=Erevan, C=AM (рег. 282.110.1004193) | Sectigo … EV R36 | **2022-11-29 … 2025-11-28 (истёк)** | `TrustedPublisher` |

Оба сертификата в `TrustedPublisher` на дату разбора (октябрь 2026) просрочены.
Просроченный сертификат **не даёт** доверия к новой подписи: проверка подписи
(драйвера `AmiconnectFlt.sys`, исполняемых файлов) завершится «издатель не доверенный»,
и появится штатное предупреждение SmartScreen/UAC. То есть шаг выглядит выполненным,
но своей задачи не решает.

Дополнительно:

1. Сертификат `AmiCert_o2.cer` выдан **сторонней организации** (STR ARM LLC, Ереван,
   Армения). Ставя его в `TrustedPublisher`, установщик расширяет доверие машины на
   подписи третьей стороны — это надо осознанно согласовывать (в отчёте это
   отдельный риск).
2. `certutil -addstore` для корневого сертификата (`Root`) выполняет установку
   корневого УЦ в системное хранилище. Сертификат AAA Certificate Services —
   публичный корень Comodo/Sectigo, который и так есть на штатной Windows, поэтому
   шаг чаще всего избыточен, но формально это операция высокого доверия.
3. Результат ни одной из пяти команд не проверяется (см. BUG-04), в том числе нет
   проверки `certutil -verify` и проверки отпечатка (SHA-1/256) — то есть
   подмена файла `.cer` в дистрибутиве не будет замечена.

## Последствия

* установщик создаёт у клиента ложное ощущение «сертификаты установлены, значит
  подпись проверена»;
* после истечения `AmiCert_o2.cer` (ноябрь 2025) обновление ПО на машинах клиента
  снова начнёт требовать подтверждения пользователя/UAC-SmartScreen, а поддержка
  будет искать причину не там;
* в хранилище навсегда остаются просроченные записи (деинсталлятор их **не удаляет** —
  проверено: в деинсталляторе нет ни одной операции с хранилищем сертификатов).

## Что должно быть

1. Обновлять сертификаты в комплекте поставки (и/или не включать их,
   если они не нужны: доверие к подписи EV-сертификата уже приходит с
   кросс-сертификатами Sectigo).
2. Проверять результат каждой команды и срок действия:

```nsis
nsExec::ExecToLog '"$SYSDIR\certutil.exe" -addstore "TrustedPublisher" "$INSTDIR\AmiCert_o2.cer"'
Pop $0
StrCmp $0 "0" +3 0
  MessageBox MB_ICONSTOP "Не удалось установить сертификат издателя (код $0)"
```

3. Удалять сертификаты при деинсталляции (`certutil -delstore`) либо явно
   документировать, что они остаются.
