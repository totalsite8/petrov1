# NOTE-01. Прочие наблюдения (не дефекты в строгом смысле)

Список мелочей и «запахов» кода, найденных при разборе скрипта. Номера — инструкции
в `../decompiled/functions.txt` (установщик) и
`../decompiled_uninstaller/functions.txt` (деинсталлятор).

## 1. Журнал `$INSTDIR\Install.log`

* Открывается дважды по-разному: при первом обращении — `CREATE_ALWAYS`
  (`access=0x40000000 creat=2`, инструкция 212), далее — `OPEN_EXISTING` (210).
  Значит, журнал предыдущего запуска **усекается** (для диагностики истории это плохо).
* Перед каждым *добавляемым* блоком дописываются два байта `FF FE`
  (`FileWriteByte $5 255` / `254`, инструкции 217–218 и все их копии: 1088–1089,
  1154–1155, 2007–2008, 2438–2439, 2462–2463, 1646–1647 в установщике; 290–291 в
  деинсталляторе). Если файл пуст, BOM не пишется (216) — в итоге первая часть
  журнала идёт без BOM, а каждая следующая — с BOM: файл не является корректным
  UTF-16-потоком (лишние `U+FEFF` в середине).
* Журнал пишется по пути `$INSTDIR\Install.log` ещё из `.onInit`, до того как
  каталог установки создан: если `$INSTDIR` не существует, `FileOpen` вернёт 0,
  и часть диагностики будет молча потеряна (обработка `IntCmp $5 0` только
  пропускает запись).

## 2. Мёртвая проверка строкового кода возврата

```
1585  StrCmp $1 "error" label_1499 0
1587  IntCmp $1 0 label_1588 label_1499 label_1499
```

Инструкция 1585 сравнивает **числовой** код возврата `ADrvInst /t /s` со строкой
`"error"` — такое условие не выполнится никогда (строка 1587 делает корректную
проверку).

## 3. Принудительное завершение клиента

```
установщик 869:  taskkill /f /t /im amiconnect.exe
деинсталлятор 104: taskkill /f /t /im amiconnect.exe
```

Убиваются процессы **всех** пользователей, без предупреждения и без проверки
результата: активный VPN-туннель обрывается, несохранённые данные пользователя
могут быть потеряны. Обычно достаточно вежливого завершения и предупреждения.

## 4. Недокументированный перезапуск из `%TEMP%` с ключом `/ANP`

```
2160  CopyFiles "$EXEPATH" "$TEMP"
2164  ExecWait "$\"$TEMP\$EXEFILE$\" $0 /ANP"
2166  Delete "$TEMP\$EXEFILE"
```

Если установщик запущен с сетевого диска/из пути, откуда он не может работать
напрямую, он копирует себя в `%TEMP%` и перезапускается с ключом `/ANP`.
Ключ не описан в строке справки установщика (`[/S [/W] [/R]] [/D=] [/LT]`),
а по аварийному пути копия не удаляется (`Delete` на 2166 достигается только
при успешном выполнении).

## 5. Нет проверки возможности установки перед удалением старой версии

Установщик сначала останавливает службу, удаляет драйвер и старые файлы
(инструкции 855–1131), и только потом распаковывает новые (`1411–1422`).
Проверки свободного места, версии ОС и совместимости нет; откат предусмотрен
только для одного случая (ошибка установки драйвера — запуск сохранённого
`amiconnect-uninst.exe`, инструкции 1283, 1574), т.е. при сбое на середине
система может остаться без рабочего драйвера.

## 6. Удаление каталога данных **всех** пользователей

Деинсталлятор обходит каталоги профилей (`$PROFILE\..` + `FindFirst`,
инструкции 266–275) и удаляет `%LOCALAPPDATA%\Amiconnect` у каждого найденного
пользователя, включая неактивных. Для многопользовательских терминальных серверов
это надо делать осознанно (комментарий в коде отсутствует).

## 7. Права записи для всех пользователей на конфигурацию

```
1610–1629  AccessControl::GrantOnFile "$INSTDIR\csat.conf" "(S-1-5-32-545)" "GenericRead+GenericWrite"
           AccessControl::GrantOnFile "$INSTDIR\cfg.ini"     "(S-1-5-32-545)" "GenericRead+GenericWrite"
           AccessControl::GrantOnFile "$INSTDIR\status.json" "(S-1-5-32-545)" "GenericRead+GenericWrite"
```

`S-1-5-32-545` — встроенная группа «Пользователи». Подробный разбор последствий
(включая каталог журналов `log` со правами `FullAccess`) — в `SEC-03`.

## 8. Отладочные сообщения в интерфейсе

```
1074  DetailPrint "New INSTDIR != Old"
2448  DetailPrint "No"
```

Строки выглядят как отладочные и попадают в окно деталей и в журнал.

## 9. Временные копии в каталоге установки

`ADrvInst.exe` (100 168 Б) распаковывается дважды — в
`$INSTDIR\Drivers\AmiconnectFlt\` (1137) и в `%TEMP%\AMICLIENT\` (1748) — и
вызывается то из одного, то из другого места (1168/1176/1183/1187/1196 против 1581),
а в конце установки копия из `$INSTDIR\Drivers\AmiconnectFlt` удаляется (1828–1829).
Постоянного дублирования нет, но в `$INSTDIR\Drivers\AmiconnectFlt` остаётся
вторая копия `AmiconnectFlt.sys` (228 КБ) — та же, что уже лежит в
`%WINDIR%\System32\drivers`. Каталог нужен только для последующего удаления
(деинсталлятор берёт из него `.inf`) и в работе клиента не участвует.

## 10. Деинсталлятор распаковывает `.inf`/`.cat` туда, где они не нужны

В деинсталляторе не задан `SetOutPath`, поэтому `$OUTDIR` равен `$INSTDIR`
(так его инициализирует exehead при перезапуске с `_?=<каталог>` — `Main.c`,
`mystrcpy(state_output_directory, p)`). В результате:

* `File "ADrvInst.exe"` (121) → `$INSTDIR\ADrvInst.exe` — нужен, потому что все
  вызовы идут по этому пути (125/134);
* `File "AmiconnectFlt.inf"` (119) и `File "amiconnectflt.cat"` (120) → `$INSTDIR\`
  — их содержимое не используется: `ADrvInst` получает `.inf` из
  `$INSTDIR\Drivers\AmiconnectFlt\` (125/134). Остаются лежать до
  `RMDir /r $INSTDIR`; если удаление отложено до перезагрузки, `.inf`, `.cat` и
  `ADrvInst.exe` остаются на диске.

## 11. Версии драйвера в трёх файлах не совпадают

* `AmiconnectFlt.sys` — `FileVersion 1.18.2887.0`;
* `AmiconnectFlt.inf` — `DriverVer = 04/13/2026,1.12.2207.0`;
* продукт в целом — `1.30.3004`.

Драйвер ставится через `ADrvInst.exe`, который использует версию из `.inf`;
расхождение версий в `.sys`/`.inf` усложняет диагностику («какая версия драйвера
стоит на самом деле») и может приводить к тому, что обновление драйвера в
магазине драйверов не подхватится.

## 12. Правка пользовательских конфигураций регулярным выражением PowerShell

`Function_282` («Fixing user configuration...») обходит каталоги профилей и для
каждого `AppData\Local\Amiconnect\cfg.ini` выполняет (`341–345`):

```
powershell -WindowStyle hidden -command "(Get-Content '<cfg.ini>') -replace '\"ALLOWNOVPNIPPACK\"\s*:\s*0', '\"ALLOWNOVPNIPPACK\": 1' | Set-Content '<cfg.ini>'"
```

* это уже второй скрытый запуск PowerShell в установщике (первый — см. `SEC-02`),
  здесь ещё и с правкой файлов пользователя от имени администратора;
* правка текста регулярным выражением вместо разбора JSON: сломанный/нестандартный
  JSON будет перезаписан (`Set-Content` меняет кодировку и переводы строк), а
  ошибка (см. `Failed to modify $4 (error $8)`) только пишется в журнал;
* результат запуска (`Pop $8`) пишется в лог, но не влияет на установку.

## 13. Фиксированные паузы

`Sleep 2000`, `Sleep 3333`, `Sleep 16949`-строки (инструкции 745, 790, 793, 1132,
1169, 1191, 1421, 2125 и др.) используются как «ожидание готовности» драйвера,
службы и завершения процессов. На медленных машинах это источник гонок; надёжнее
ждать события (например, опрашивать состояние службы циклом с ограничением).

## 14. Сертификаты не удаляются при деинсталляции

В деинсталляторе нет ни одного вызова `certutil`/операции с хранилищами:
пять сертификатов, установленных при инсталляции, остаются в системе навсегда.

## 15. Маска удаления

```
1410  Delete "$INSTDIR\amiconnect.*"
```

Маска удаляет не только файлы самого продукта (`amiconnect.exe`,
`amiconnectd.exe`, `amiconnect-mtu.ps1`, `amiconnect-uninst.exe`), но и любые
пользовательские файлы с тем же префиксом (`amiconnect.log`,
`amiconnect_backup.exe` и т. п.). Безопаснее перечислять файлы явно.

## 16. Вызов, который не может ничего сделать

```
1826  IfFlag bit=8 (silent) -> (переход)          ; IfSilent
1827  Call label_1788
1828  ...                                          ; продолжение
...
1788  SendMessage … (заголовок страницы)
1789  ClearErrors
1790  Call label_194                                ; вывод журнала
1791  IfFlag bit=8 (silent) -> label_1824          ; IfSilent → сразу Return
...
1824  Return
```

Вызов `Call label_1788` (1827) исполняется **только** в тихом режиме (`/S`), а сама
`label_1788` в тихом режиме сразу возвращает управление (1791 → 1824). То есть
инструкция не делает ничего: при `/S` она возвращается назад, без `/S` — не
вызывается вовсе. Похоже на остаток отладки/сборки страницы «детали установки».
