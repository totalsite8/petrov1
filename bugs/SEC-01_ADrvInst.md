# SEC-01. `ADrvInst.exe`: временный локальный администратор, запрос на отключение антивируса

* **Важность:** средняя (ИБ-риск; требует осознанного согласования при внедрении)
* **Компонент:** `extracted/payload/ADrvInst.exe` (100 168 Б, версия 7.0.0.0),
  запускается установщиком (инструкции 1168, 1176, 1183, 1187, 1196) и деинсталлятором (125, 134)

## Что делает утилита

Это отдельный исполняемый файл, который установщик вызывает с ключами
`/u`, `/do`, `/o`, `/i /s`, `/t /s` (разбор параметров — только по местам вызова,
строки справки в файле отсутствуют). По импортам и строкам видно:

| Импорт / строка | Что означает |
|---|---|
| `NETAPI32.dll: NetUserAdd`, `NetLocalGroupAddMembers` | создание учётной записи и добавление её в группу |
| строка `DrvSlntLocalAdmInst` | имя временной учётной записи («Silent Local Admin») |
| `ADVAPI32.dll: LogonUserW`, `ImpersonateLoggedOnUser`, `DuplicateTokenEx`, `CreateProcessAsUserW` | вход под этой записью, имперсонация и запуск процесса от её имени |
| `OpenProcessToken`, `LookupPrivilegeValueW`, `AdjustTokenPrivileges`, `SeLoadDriverPrivilege`, `SeTcbPrivilege` | включение привилегий загрузки драйвера и `SeTcb` |
| `SETUPAPI.dll: SetupCopyOEMInfW`, `newdev.dll: UpdateDriverForPlugAndPlayDevicesW` | установка драйвера в хранилище драйверов и привязка к устройству |
| `ADVAPI32.dll: OpenSCManagerW`, `ChangeServiceConfigW`, `StartServiceW` | правка и запуск службы драйвера |
| `ROOT\SecurityCenter`, `SELECT * FROM AntivirusProduct` | перечисление установленных антивирусов через WMI |
| `(There are some antivirus programs installed):`, `(Disable antivirus security for succesfull installation and press OK!)` | предложение пользователю **отключить антивирус** (орфография ошибки сохранена — «succesfull») |

## Почему это риск

1. **Создание временного локального администратора** (`NetUserAdd` +
   `NetLocalGroupAddMembers` + `LogonUserW` + `CreateProcessAsUserW`) — это ровно тот
   приём, который используют эксплойты и «тихие» установщики драйверов, чтобы обойти
   ограничения токена пользователя. Даже если запись удаляется в конце, на машине
   появляется и исчезает административная учётная запись, что фиксируется в журналах
   безопасности и может блокироваться политиками (LSA-ограничения, EDR).
2. **Просьба отключить антивирус** во время установки снижает защищённость машины на
   время установки и приучает пользователя к опасному действию. Современные
   EDR/антивирусы могут блокировать установку NDIS-фильтра — правильное решение это
   подписанный драйвер с WHQL-подписью, а не отключение защиты.
3. **Привилегии `SeLoadDriver`/`SeTcb`** в паре с WMI-опросом списка антивирусов дают
   утилите полный контроль над драйверной подсистемой.
4. Формальных сведений о том, что утилита удаляет временную учётную запись в конце
   работы, в тексте нет (строки `NetUserDel` в импортах отсутствуют — проверить
   удаление можно только динамически; см. «Ограничения» в `../ОТЧЁТ.md`).

## Рекомендации

* по возможности отказаться от самодельного установщика драйвера в пользу
  `pnputil /add-driver … /install` от имени уже повышенного процесса;
* не запрашивать отключение антивируса; вместо этого обеспечить WHQL-подпись
  драйвера и корректный INF;
* документировать, что установщик создаёт временную локальную учётную запись
  (и гарантировать её удаление в `finally`-логике);
* для корпоративного развёртывания — заранее согласовать с ИБ и добавить
  установщик в исключения EDR осознанно, а не «по кнопке OK».

## Как проверить самому

```bash
strings -el extracted/payload/ADrvInst.exe | grep -i -E "antivirus|DrvSlnt|SecurityCenter"
# или
python3 - <<'EOF'
import pefile; pe=pefile.PE('extracted/payload/ADrvInst.exe')
for d in pe.DIRECTORY_ENTRY_IMPORT:
    if d.dll.lower() in (b'netapi32.dll', b'advapi32.dll'):
        print(d.dll, [i.name for i in d.imports][:20])
EOF
```
