# SEC-03. Полные права группы «Пользователи» на каталог журналов службы и служебные файлы

* **Важность:** средняя (ИБ; потенциальное локальное повышение привилегий,
  подмена конфигурации и журналов)
* **Компонент:** установщик, секция 0 (права на файлы), служба `amiconnectd`
* **Инструкции:** 1426 (создание `$INSTDIR\log`), 1481–1482 (выдача прав),
  1612–1629 (права на `csat.conf`, `cfg.ini`, `status.json`)

## Что делает установщик

```
1426  CreateDirectory "$INSTDIR\log"
      ...
1481  Push "$INSTDIR\log"
1480  Push "(S-1-5-32-545)"          ; BUILTIN\Users
1479  Push "FullAccess"
1482  CallInstDLL/Plugin "$PLUGINSDIR\AccessControl.dll" (func="GrantOnFile")
      ...
1614  Push "$INSTDIR\csat.conf"      1621  Push "$INSTDIR\cfg.ini"
1613  Push "(S-1-5-32-545)"           1620  Push "(S-1-5-32-545)"
1612  Push "GenericRead+GenericWrite" 1619  Push "GenericRead+GenericWrite"
1615/1622  CallInstDLL/Plugin "…\AccessControl.dll" (func="GrantOnFile")
1628  Push "$INSTDIR\status.json"    1627  Push "(S-1-5-32-545)"
1626  Push "GenericRead+GenericWrite"
1629  CallInstDLL/Plugin "…\AccessControl.dll" (func="GrantOnFile")
```

Все три вызова плагина не проверяются: сразу после них идёт только
`Call label_2742` / `SetFlag bit=13` (подготовка следующего плагина), код возврата
`AccessControl` не анализируется.

Дополнительно: служба создаётся как `sc create amiconnectd start= auto …`
(**без** `obj=`, т.е. от имени `LocalSystem`), а файлы журналов, судя по строкам
бинарников, лежат именно в этом каталоге:

* `amiconnectd.exe` → `\SrvLog.csv`
* `amiconnect.exe` → `\ClientLog.csv`, `SrvLog.csv`

## Почему это риск

1. **Запись в каталог привилегированного процесса.** Служба `amiconnectd`
   работает от `LocalSystem` и пишет CSV-журнал в `$INSTDIR\log`, где любой
   локальный пользователь имеет `FullAccess`. Схема «привилегированный процесс
   пишет в каталог, доступный на запись непривилегированному пользователю» —
   классический источник локального повышения привилегий (подмена файла на
   символическую ссылку/точку монтирования, подмена содержимого журнала,
   исчерпание диска). Проверка требует динамического эксперимента (какие именно
   операции выполняет служба), поэтому дефект помечен как «потенциальный», но
   выдача `FullAccess` на каталог журналов здесь точно избыточна: достаточно
   `Modify` на сам файл журнала или отдельного подкаталога.
2. **Подмена конфигурации.** `csat.conf` содержит адрес сервиса проверки
   соответствия (`address`, `appId`) и читается GUI-клиентом пользователя, а
   `status.json` — состояние проверки соответствия (`COMPLIANCE: status.json
   nudge`, `Got status.json from FPSU` в строках службы). Любой пользователь
   машины может изменить оба файла: подменить адрес проверки, подделать статус
   «соответствует» в журнале/интерфейсе.
3. **Права выдаются на этапе установки и никогда не отзываются** (деинсталлятор
   удаляет каталог целиком, промежуточных изменений ACL не делает), поэтому
   ослабленные права действуют всё время эксплуатации.

## Что стоит сделать

* выдавать «Пользователям» только `GenericRead` на `csat.conf`, `status.json` и
  `GenericRead+GenericWrite` только на те файлы, которые действительно правит
  непривилегированный GUI (`cfg.ini`);
* журналы службы перенести в `%ProgramData%\AMICON\Amiconnect\log` с ACL
  «SYSTEM — FullControl, Users — Read», либо ограничиться `Modify` на файл;
* файлы, которые пишет сама служба, не размещать в каталогах с правом записи для
  `Users`; проверять существование и жёстко задавать владельца каталога перед
  первой записью;
* проверять код возврата `AccessControl::GrantOnFile` и писать в журнал
  фактический результат, а не «предполагаем, что получилось».

## Как проверить самому

```bash
grep -n "GrantOnFile" decompiled/functions.txt          # 1482, 1615, 1622, 1629
grep -n "CreateDirectory \"\\$INSTDIR\\\\log\"" decompiled/functions.txt   # 1426
grep -n "SrvLog.csv\|ClientLog.csv" -r extracted/payload 2>/dev/null     # строки в amiconnect*.exe
```

Динамическая проверка (на тестовой машине): `icacls "%ProgramFiles%\AMICON\Amiconnect\log"`
до и после установки, затем попытка непривилегированного пользователя подменить
`SrvLog.csv` при работающей службе.
