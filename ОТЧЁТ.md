# Реверс-инжиниринг установщика Amiconnect 1.30.3004

**Объект анализа:** `Amiconnect_1_30_3004_Win.exe` (8 606 592 байт,
SHA-256 `c905e64aae608b162e3934abe7f6086127ebe4bb1650176956cd00ec52336449`)
**Результат:** полностью восстановлен скрипт установщика (2761 инструкция), скрипт
деинсталлятора (831 инструкция), извлечены все 29 вложенных файлов, составлена карта
структуры, разобрано назначение ПО и найдено 6 дефектов + 4 замечания по
безопасности/качеству (см. каталог [`bugs/`](bugs/)).

## 1. Что это за файл

Москва) для Windows 10/11 x64. Собран в NSIS 3.12.2, вариант **NSISBI** (64-битный форк
NSIS). Установщик упакован целиком (стаб + сжатый «поток данных» LZMA).

## 2. Как выполнена декомпиляция

Стандартные средства (7-Zip, `nsis_extractor`, `NSISExtractor`, `7z -tNsis`) этот файл
**не открывают**: NSISBI отличается форматом «потока данных» (9-двоичные записи,
64-битные смещения, нулевые дескрипторы части блоков). Поэтому формат восстановлен
«с нуля» и сверен с исходниками NSISBI и 7-Zip, после чего написан собственный
декомпилятор (`tools/`).

Порядок работы (всё воспроизводимо одной командой, см. §5):

1. **Найдена подпись** `0xDEADBEEF "NullsoftInst"` — файл `0x1A804`.
2. **Распакованы LZMA-блоки**: сразу за подписью идут блоки вида
   `u24 length | 5 байт свойств LZMA1 | (length-5) байт потока LZMA1`
   (8 блоков → 28 657 684 байта). Склейка = «поток NSISBI».
3. **Разобран поток**: `u64 length_of_header`, `u32 flags`, 8 дескрипторов блоков
   (pages/sections/entries/strings/langtables/ctlcolors/bgfont/data), общий header,
   таблица строк, таблица языков, упакованные файлы.
4. **Восстановлены записи инструкций** (36 байт: `which` + 8 параметров) и написан
   дизассемблер с мнемониками NSIS (более 70 опкодов) — семантика параметров сверена
   построчно с `Source/exehead/exec.c` NSISBI.
5. **Извлечены все файлы** (упакованные данные: `u64 размер` + данные) — 29 уникальных
   файлов с проверкой SHA-256.
6. **Извлечён вложенный деинсталлятор**: инструкция `EW_WRITEUNINSTALLER` (запись 794)
   указывает на `0x1B419C5` потока; оттуда по той же схеме распакованы 2 LZMA-блока
   (235 480 байт) — это полноценный поток NSISBI со своим скриптом.
7. **Дизассемблирован** и он: 831 инструкция, 5 страниц, 2 секции
   («Uninstall», «Amiconnect configuration»).

Особенность формата, важная для чтения листингов: **все строковые и числовые
параметры инструкций — это смещения в таблицу строк** (`u16`-символы, NUL-терминатор),
причём компилятор использует «суффиксное разделение»: указатель может вести в середину
другой строки (`$INSTDIR\License.txt` → строка `License.txt`). Исполняющая система
преобразует такие параметры в числа через `myatoi()`, поэтому в листингах числовые
параметры печатаются как числа, а переменные — как `$VarNN`.

## 4. Краткие итоги

**Что делает установщик** (детали — в `АНАЛИЗ_ПРОГРАММЫ.md`):

* проверяет права администратора, отсутствие терминальной сессии и версию ОС;
* при запуске с сетевого диска копирует себя в `%TEMP%` и перезапускается с ключом `/ANP`;
* устанавливает в хранилища машины 5 сертификатов (`certutil -addstore`, в т.ч. в
  `TrustedPublisher` — «доверенные издатели»);
* останавливает и удаляет прежнюю службу `amiconnectd`, чистит прежние ярлыки и файлы;
* устанавливает NDIS-фильтр `AmiconnectFlt.sys` через `ADrvInst.exe` (запуск `/u`, `/do`,
  `/o`, `/i /s`, `/t /s`, затем `copy /y` в `SYSTEM32\DRIVERS`);
* прописывает автозапуск, запись в «Установка и удаление программ», параметры службы
  (`sc create/failure/failureflag`, автоперезапуск) и разрешение в брандмауэре;
* пишет `amiconnect-uninst.exe` (деинсталлятор), создаёт ярлыки, запускает
  `amiconnect-mtu.ps1 -Mode Save` (снижение MTU до 1400 у физических адаптеров
  с сохранением исходных значений в реестр) и запускает GUI.

**Найденные дефекты** (6 дефектов + 3 замечания по безопасности/качеству; сводка и
приоритеты — в [`bugs/БАГРЕПОРТ.md`](bugs/БАГРЕПОРТ.md), доказательства — в отдельных файлах):

## 5. Как воспроизвести

```bash
# 1. распаковка потока установщика и вложенного деинсталлятора
python3 tools/unpack_nsisbi.py Amiconnect_1_30_3004_Win.exe -o work/

# 2. декомпиляция обоих скриптов
python3 tools/decompile_stream.py work/installer_stream.bin   decompiled            extracted/payload
python3 tools/decompile_stream.py work/uninstaller_stream.bin decompiled_uninstaller extracted/uninstaller_payload
```

Требуется только Python 3.11+ (модуль `lzma` из стандартной библиотеки).
Скрипты не используют внешних зависимостей; `tools/nsisdec.py` — библиотека формата
(header, таблица строк, секции, страницы, записи, дизассемблер).

Ожидаемый результат (проверено):

```
подпись NSISBI      : 0x1a804
начало LZMA-блоков  : 0x1a824
поток установщика   : 28657684 байт (до 0x832988, размер файла 0x835380)
записей инструкций  : 2761
упакованных файлов  : 108
область данных      : 0x29562
деинсталлятор       : смещение в потоке 0x1b419c5, подпись 0x3be, 235480 байт
```

## 6. Ограничения

* **UI-опкоды.** Часть опкодов интерфейса (`LockWindow`, `SendMessage`, `ShowWindow`,
  `LoadAndSetImage`) разобрана не до конца: тип и роль отдельных параметров в NSISBI
  отличаются от «обычного» NSIS и в исходниках проверены лишь частично. Логика
  установки/удаления от них не зависит.
* **Проверка на «живой» системе.** Дефекты выведены из кода и внешних фактов (пути,
  сроки действия сертификатов, поведение утилит Windows). Динамических испытаний
  (запуск установщика на виртуальной машине) не проводилось — для BUG-03 и BUG-05
  влияние зависит от версии Windows и настроек безопасности машины.
* **Восстановленный `.nsi`.** Исходный скрипт восстанавливается «как есть» по коду, но
  имена макросов/функций и комментарии автора утеряны (в NSISBI строка `File` хранит
  только имя, а метки безымянные); в листингах функции названы по адресу первой
  инструкции (`Function_906` и т.п.).
* **Установщик не запускался.** Файл анализировался статически; рабочие копии
  `patched_*.exe`, использовавшиеся при подборе формата, удалены.
