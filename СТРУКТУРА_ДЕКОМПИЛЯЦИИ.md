# Структура декомпиляции `Amiconnect_1_30_3004_Win.exe`

Документ описывает, **как устроен разобранный установщик** и **как читать
результаты декомпиляции** в этом репозитории. Сама методика распаковки и
ограничения — в [`ОТЧЁТ.md`](ОТЧЁТ.md), назначение программы — в
[`АНАЛИЗ_ПРОГРАММЫ.md`](АНАЛИЗ_ПРОГРАММЫ.md).

---

## 1. Что это за формат

Файл — самораспаковывающийся установщик **NSISBI** (вариант NSIS с 64-битными
смещениями и поддержкой «больших» установщиков; официальный форк
`nsisbi`/`nsisbi_mirror`), собранный NSIS 3.12.2.

Стандартные средства (`7-Zip` ≤ 23.01, `nsis_extractor`, NSISExtractor) его
**не видят**: отличается формат упакованного «потока данных» (записи по
36 байт с 9-двоичными операндами, дескрипторы блоков, часть которых занулена).
Поэтому формат восстановлен по исходникам NSISBI и 7-Zip и реализован в
`tools/nsisdec.py`.

## 2. Уровень 1 — файл

```
0x000000  PE32+ (x64), GUI, requireAdministrator, версия ресурса 1.30.3004
0x01A804  подпись NSIS: EF BE AD DE "NullsoftInst"
0x01A80C  firstheader: flags=0x01B2B2B2 (FH_FLAGS_*), siginfo=0, …
0x01A824  8 блоков LZMA1: [u24 length][5 байт свойств LZMA1][length-5 байт данных]
          ── распаковка ──►  «поток NSISBI», 28 657 684 байта
0x832988  (конец последнего блока)
0x835380  конец файла
```

## 3. Уровень 2 — поток NSISBI

```
+0x00000  u64 length_of_header        (= 0x2955A; область данных начинается по H+это_значение)
+0x00008  u32 flags
+0x0000C  8 × дескриптор блока: u64 offset | u32 num
           0 pages      0x14C  7
           1 sections   0x30C  3
           2 entries    0x1B54 2761
           3 strings    0x19F98 (num не заполнен)
           4 langtables 0x2927A 2
           5 ctlcolors  0x29506 (num не заполнен)
           6 bgfont     0
           7 data       0   ← в этом сборке занулён, область данных считается по length_of_header
+0x0014C  header: ключ реестра, каталог установки, callback-и .onInit/.onGUIInit/…,
          цвета, install-types, размер таблицы языков, номер языка установки
+0x0014C …  страницы (64 Б × 7)
+0x0030C …  секции (2072 Б × 3)
+0x1B54  …  записи инструкций (36 Б × 2761)
+0x19F98 …  таблица строк (UTF-16LE, NUL-разделители + escape-коды 0x0001/0x0002/0x0003)
+0x2927A …  таблицы языков (2 языка: 1049 русский, 1033 английский)
+0x29506 …  цвета контролов
+0x29562 …  область данных: упакованные файлы (u64 размер | данные) и образ деинсталлятора
```

### Запись инструкции (36 байт)

```
u32 which          — код операции (EW_*)
u32 parm[0..7]     — 8 операндов; смысл зависит от операции (см. §5)
```

### Как читать операнды

| Правило | Пояснение |
|---|---|
| **Строка** | операнд — смещение в таблице строк (в **символах**, не в байтах): `GetNSISStringNP(strtab) = g_blocks[NB_STRINGS].offset + strtab` |
| **Число** | движок всегда вызывает `myatoi(GetNSISString(param))`, поэтому числовые литералы компилятор тоже кладёт в таблицу строк (`"2"`, `"1049"`, …) |
| **Переменная** | ссылка на переменную хранится escape-кодом `0x0003` → в листинге выглядит как `$0`, `$R1`, `$LANGUAGE`, `$Var61` |
| **Суффиксное разделение** | смещение может указывать **внутрь** другой строки: `17495` → `License.txt` внутри `$INSTDIR\License.txt`, `15332` → `9` внутри `1019`. Это не ошибка формата, а экономия таблицы строк |
| **Отрицательные значения** | `-N` (как `0xFFFFFFD8`) — встроенная строка exehead’а (`$(BRANDING)`, `$(CAPTION)`, … — см. `Source/exehead/lang.h`), а не номер переменной |
| **Смещения данных** | `File`/`WriteUninstaller` дают смещение относительно начала области данных (`+0x29562`), перед данными лежит `u64` размер (старший бит = признак LZMA) |
| **Метки** | в листингах `label_N` = запись номер `N`; `Goto`/`Call`/переходы в листинге уже пересчитаны в номера записей |

### Флаги (`SetFlag` / `IfFlag` / `GetFlag`)

Операнд `bit=N` — это индекс поля внутренней структуры состояния exehead
(`exec_flags_t`); имена полей и их порядок взяты из `NsisIn.cpp`
(`kExecFlags_VarsNames`), что проверено на этом скрипте: `SetFlag bit=13 value=6`
генерируется компилятором NSISBI в служебной функции `label_2742`
(`FLAG_OFFSET(status_update)`), а `13` — это как раз индекс `status_update`.

| `bit` | Поле | Команда NSIS | Что означает в листинге |
|---|---|---|---|
| 0 | `autoclose` | `SetAutoClose` | автозакрытие окна по завершении |
| 1 | `all_user_var` | `SetShellVarContext` | 1 = «все пользователи», 0 = «текущий» |
| 2 | `exec_error` | `ClearErrors` / `SetErrors` / `IfErrors` | `SetFlag bit=2 value=0` = ClearErrors, `value=1` = SetErrors |
| 3 | `abort` | `IfAbort` | флаг нажатия «Отмена» (ставит сам exehead) |
| 4 | `exec_reboot` | `SetRebootFlag` / `GetRebootFlag` | `value=1` = требуется перезагрузка |
| 8 | `silent` | `IfSilent` | тихий режим (`/S`) |
| 9 | `instdir_error` | `IfFileExists`-проверка каталога | причина отказа |
| 11 | `errlvl` | `SetErrorLevel` / `GetErrorLevel` | **код выхода** установщика: 1 — отказ/ошибка, 2 — «нужна перезагрузка», 3 — «нет прав администратора» |
| 12 | `alter_reg_view` | `SetRegView` | 0x100 (256) = 64-битный вид, 0x200 (512) = 32-битный, 0 = по умолчанию |
| 13 | `status_update` | `SetDetailsPrint` | режим вывода в окно деталей (служебный) |

Поэтому, например, `SetFlag bit=2 value=0` в начале каждой проверки — это
`ClearErrors`, а `SetFlag bit=12 value=512` — `SetRegView 32` (а не «код выхода
512»): в коде вокруг `Wow64DisableWow64FsRedirection` установщик так переключает
вид реестра.

## 4. Что в каком файле результата

| Файл | Содержимое |
|---|---|
| `decompiled/disasm.txt` | все 2761 инструкций подряд, с `which` и разобранными операндами |
| `decompiled/functions.txt` | то же, но сгруппировано по функциям/секциям/callback-ам (основной файл для чтения) |
| `decompiled/key_ops.txt` | только «содержательные» операции: `File`, `SetOutPath`, `WriteReg*`, `Exec`, плагины, `WriteUninstaller`, ярлыки |
| `decompiled/strings.txt` | таблица строк установщика (смещение → текст) |
| `decompiled/payload_files.json` | 108 записей `File` → имя, смещение, размер, SHA-256 |
| `decompiled_uninstaller/*` | то же для встроенного деинсталлятора (831 инструкция, 5 страниц, 2 секции) |
| `extracted/payload/`, `extracted/plugins/`, `extracted/uninstaller_payload/` | распакованные файлы (29 уникальных + 9 в деинсталляторе) |
| `tools/nsisdec.py` | библиотека формата: разбор потока + дизассемблер NSIS |
| `tools/decompile_stream.py` | декомпиляция произвольного потока (`python3 tools/decompile_stream.py <stream> <outdir> [extractdir]`) |
| `tools/unpack_nsisbi.py` | распаковка установщика/деинсталлятора из EXE |

## 6. Порядок работы установщика (по коду)

1. `.onInit`: проверка прав администратора, сессии терминала
   (`GetSystemMetrics 4096` = SM_REMOTESESSION, `8193` = SM_REMOTECONTROL),
   разбор ключей, при работе с сетевого пути — копирование себя в `%TEMP%` и
   перезапуск с `/ANP`, диалог выбора языка (LangDLL, 1049/1033), определение
   `$INSTDIR` (по умолчанию `program files\AMICON\Amiconnect` через
   `$SHELLREG("ProgramFilesDir")`), запись в реестр.
2. Секция 0: остановка прежней службы (`sc failure … reset= 0 actions= ""`,
   `net stop`, `taskkill`), удаление прежней установки (`RMDir /r $1`, где `$1`
   взято из `HKLM\SOFTWARE\AMICON\Amiconnect\Install_Dir`), чистка ярлыков и
   правил брандмауэра, распаковка драйвера в `$INSTDIR\Drivers\AmiconnectFlt`,
   `certutil -addstore` (Root/CA/TrustedPublisher ×5), лицензия (`License.txt`
   RU/EN из `$Var52\AMICLIENT`), `WriteUninstaller`, установка драйвера через
   `ADrvInst.exe` (`/u`, `/do`, `/o`, `/i /s`, `/t /s`), `copy /y` драйвера
   (не выполняется — см. `bugs/BUG-02`), распаковка клиента и службы,
   регистрация службы (`sc create/failure/failureflag`, `ADrvInst /t /s amiconnectd`),
   правило брандмауэра, права на конфиги, `net start amiconnectd`.
3. Секция 1: `amiconnect-mtu.ps1 -Mode Save` (MTU 1400 у физических адаптеров,
   кроме виртуальных и сторонних VPN; см. `bugs/SEC-02`).
4. Секция 2: ярлыки в меню «Пуск» (RU/EN — с инверсией, см. `bugs/BUG-01`).
5. `.onInstSuccess`: запуск `amiconnect.exe`.

## 7. Порядок работы деинсталлятора (по коду)

1. `.onInit`: проверки, при необходимости — самоперезапуск с `/S`.
2. Секция 0: `sc failure … reset= 0 actions= ""`, `net stop`, `taskkill`,
   удаление службы (`sc delete` + `DeleteRegKey`), распаковка `ADrvInst`/`.inf`/`.cat`,
   `ADrvInst /u`, `Sleep 3333`, удаление `.sys`, `ADrvInst /do`,
   `powershell amiconnect-mtu.ps1 -Mode Restore`, удаление ярлыков обеих
   языковых папок, правила брандмауэра, ключей `Run` и
   `SOFTWARE\AMICON\Amiconnect` + записи «Установка и удаление программ»,
   `RMDir /r /REBOOTOK $INSTDIR`, код выхода в `$Var53`.
3. Секция 1: журнал и `RMDir /r "$Var52\AMICLIENT"`.
4. `.onInstSuccess`: удаление `%LOCALAPPDATA%\Amiconnect` у всех профилей.

## 8. Ограничения разбора

* Операции уровня интерфейса (`LockWindow`, `SendMessage`, `ShowWindow`,
  `LoadAndSetImage`, `SetCtlColors`) в NSISBI используют ту же нумерацию опкодов,
  что и NSIS, но часть их операндов (например, указатели на структуры цветов)
  выводится «как есть». Логика установки/удаления от них не зависит.
* Имена функций (`Function_N`), меток (`label_N`) и переменных (`$VarNN`) —
  восстановленные: в скомпилированном скрипте имён нет, кроме текстов,
  указанных в таблице строк.
* Инструкции `EW_RESERVEDOPCODE` (6 шт.) и все неизвестные коды печатаются
  как есть — в этом файле «неизвестных» не встречено.
